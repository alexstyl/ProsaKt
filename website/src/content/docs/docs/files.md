## File structure

`ktFile { ... }` returns a string in this order:

1. File annotations.
2. Package declaration, if configured.
3. Collected and explicit imports.
4. Declarations in the order you added them.

Sections are separated by blank lines, and the file ends with a newline. `packageName("example.generated")` is optional and can only be configured once.

## File annotations

```kotlin
val source = ktFile {
    ktFileAnnotation("kotlin.jvm.JvmName") {
        argument { literal("GeneratedApi") }
    }
    packageName("example")
    ktValue("version") { initializer { literal("0.1.0") } }
}
```

File annotations emit the `@file:` prefix. Their arguments use the same value-argument builder as calls, including named arguments.

## Comments and spacing

Use `comment("Generated by my tool")` for a line comment. Multi-line text becomes multiple line comments. `line()` inserts a blank line; `lines(2)` inserts two.

```kotlin
val source = ktFile {
    comment("Generated by my tool")
    ktValue("first") { initializer { literal(1) } }
    line()
    ktValue("second") { initializer { literal(2) } }
}
```

## Automatic formatting

Prosa.kt uses four-space indentation and a target line width of 100 characters. It wraps structured expressions and argument lists when needed; long individual tokens can exceed that width. These settings are not configurable in the public 0.1.0 API.

Imports are resolved after collecting the file's symbols. Names that are Kotlin keywords or need escaping are wrapped in backticks.

## Scope and validation

The DSL checks structural mistakes such as an empty expression, configuring a type twice, or giving a property both an initializer and a delegate. Its scope marker also helps prevent accidentally calling builders on an outer receiver.

Prosa.kt is a source generator, not a Kotlin compiler. It does not resolve your dependencies, check types, or guarantee that arbitrary modifier and declaration combinations compile. Compile generated source in your own project when correctness depends on those checks.

Version 0.1.0 covers the builders in these guides. Features such as inheritance declarations, extension-function receivers, loops in generated code, and custom setters do not have dedicated builders yet.
